現在の変更内容から、以下のルールに従ってPRを作成してください。

## 手順
1. `git status` / `git diff` で変更内容を確認する
2. code-reviewerサブエージェントを使って、現在のブランチの変更差分をレビューする
3. レビュー結果に重大な指摘（Critical）があれば、PR作成前に修正するか、少なくとも影響範囲欄に明記する
4. 現在のブランチ名（`<type>/<issue番号>-<説明>` 形式）から Issue 番号を取得する
5. レビュー結果を踏まえて、下記テンプレートに沿って本文を作成する（見出しは変更しないこと）
6. `gh pr create --title "<タイトル>" --body "<本文>"` を実行する

## PRタイトルの形式
`<type>: <変更内容の要約>`(Conventional Commits形式)
例: `feat: ログイン画面にパスワード表示切り替えを追加`

## PR本文テンプレート

```markdown
## 概要


## 変更内容
-

## 関連Issue
Closes #<Issue番号>

## 影響範囲・破壊的変更
- 影響範囲:
- 破壊的変更: 有 / 無

## 動作確認手順
1.

## スクリーンショット・動画


## セルフレビューチェックリスト
- [ ] PRタイトルはConventional Commits形式に沿っている
- [ ] ブランチ名は `<type>/<issue番号>-<短い説明>` 形式になっている
- [ ] 動作確認手順の通りに手元で確認した
- [ ] 不要なconsole.log・デバッグコード・コメントアウトが残っていない
- [ ] 関連Issueをクローズする文言（`Closes #`）が入っている
- [ ] 破壊的変更がある場合、移行方法を記載した
```
